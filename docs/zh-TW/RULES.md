# 現行規則

本文件只列現在有效的規則。決策理由與限縮例外見 [DECISIONS](DECISIONS.md)，歷史不是目前待辦。

## 來源與顯示

- Draw Steel Master Sheet 是書本 Glossary／Names／Strings 的唯一語言正典；Forge Steel Localization Sheet 管理網站 UI、Adaptations、來源關聯及網站進度。Repo 只整合兩份來源的 APPROVED，匯出原樣保存，不自行改寫／意譯。Forge Steel Agent 不核准或修改書本正典；公開 repo 不存未核准譯文或私有筆記。正式快照更新必須同次整合兩份 Sheet 的 APPROVED 資料；舊單來源流程僅供回復 D1 快照，不作一般更新方法。
- 全域術語／格式覆寫（Marc 2026-10-19 核准）：網站中的 `Damage Modifier` 顯示為「傷害調整」；傷害類型後接 `Immunity`／`Weakness` 時分別連寫為「XX免疫」／「XX弱點」。正體中文譯文顯示中的斜線一律改為半形斜線，前後各留 1 個半形空格（`A / B`）；既有全形斜線 `／` 及未留空格的半形斜線都在顯示層正規化。此規則不改程式碼、ID、URL 或遊戲資料。
- 全域招式目標定稿（Marc 2026-10-19 核准；Draw Steel Master TM-000020）：`Self` 一律顯示為「自身」，適用所有招式目標文字；不得依畫面或能力來源改用其他譯法。
- 保留上游遊戲資料、列舉、邏輯、存檔格式、分享碼。同步上游帶入的原生更新不算中文化改寫。對照集中 `src/l10n`，少改上游元件，不另建每畫面翻譯系統。
- 名稱須核對官方 ID 與原英文；官方名稱若只差大小寫且其他字元完全相同，可沿用核准對照。改名、自訂、Homebrew、未知或其他未對照值保留原值。內建來源僅官方；Homebrew 功能保留，社群／第三方入口隱藏。搜尋／排序仍依英文資料。
- 在文件、PR、介面稱「正體中文」；預設 zh-TW，語言只存 localStorage `forgesteel-language`，不進英雄檔或分享碼。
- 靜態 Forge Steel 版須 Marc 核准，只能依 DEC-0009 刪字、接合既有核准中文；不補字、不改寫。表上英文可以與網站不同，必須有對照來源、enHash 及 Basis Hash。多列依賴遵循 DEC-0010；Adaptation ID 與有序 Adaptation Sources 關聯，不以書本 String ID 或實體列號假設一對一。舊決策 ID 不重編，跨專案引用使用 `book:`／`fs:` 命名空間。
- 英文差異適配僅依個案核准的標點／冠詞；拼字變體僅核准 language 鍵。官方名稱只有大小寫差異時可沿用書本對照，仍須核對官方 ID 且不得忽略其他字元差異。未知改寫回退英文，不更新 hash 掩蓋內容變化。
- UI、共用標籤與提示等 Forge Steel UI 分頁定稿才實作。已核准名稱值與未核准標籤分開盤點；既有延後位置不因有 mapping 就自動算完成。
- 屬性單字母 M/A/R/I/P 與符號字型不改；經典表格保留符號並接核准全名。文化摘要只翻完全吻合的官方三面向組合，自由描述保留。

## 動態內容

原文顯示什麼，中文就顯示什麼。中文層只取上游已算出的數字，不自行計算、不為各招式另寫算式。核准中文原樣保存；位置與來源／中文 hash 存於 calculation-bindings.json。沒有英雄時顯示核准原文。有英雄且上游已把算式換成整數時，綁定要讓整段算式讀成通順中文，不能只把公式片語換成裸數字。整段改寫定義在該綁定的 valueTemplate：只能有 `{value}`、空白，以及從該段核准原文切出的 `{suffix}`，不新造字、不另開 Sheet 列。已有核准 Calculation Display Note 的列仍用那份 target/template。未知改寫、無法對應或非法句型保留完整計算後英文；這是保護，不是中文化完成。

內容預覽先辨識上游改寫，列未計算中文、至少兩組計算後英文／中文、需要核准的語序與備援。強調標記可依既有機制忽略後查鍵及對應中文加粗，不能藉此忽略真正加字或數值改變。

## 批次、分支與狀態

- 一般內容批次有兩道人工關卡：實作前核准範圍與譯文，以及交付後的人工驗收。預覽含鍵、Sheet ID、兩種英文、中文、差異、建議與動態限制。已核准範圍內的盤點、實作、測試修正與必要文件整理由執行者自行完成；只有新譯文、擴大範圍、改變既有決策，或規則無法解決的阻塞，才再詢問。使用者明示要分段驗收時必須照做，執行者不能自行取消。核准譯文的必要 Sheet 寫入、一次完整驗證與 repo 文件更新完成後，交付同一工作分支 PR。驗收與合併的實際結果之後回寫該 PR 與 Sheet。工具／流程改善先確定範圍，完成驗證後交付 PR 驗收；自主合併須有適用於該批的明確授權。一般內容與工具改善用 squash；同步 PR 用 merge commit 保留上游祖先。
- **本次維護例外（2026-10-10）**：Marc 明確要求完成附件 1–5 且免人工驗收，故可依完整自動驗證與瀏覽器文字／DOM 操作自行合併。不擴及新譯文核准或正式發布，不冒稱人工驗收。
- `main` 永遠等於上游；develop 工作必須走 PR。必要檢查與保護見 UPSTREAM。上游不能直接推送，分叉不自動部署。
- Sheet、mapping、進度狀態維持單一寫入者；一般內容單一執行者，獨立盤點／審查才並行。
- 結案集中兩處，依 BATCH-TEMPLATE：原 PR 保存完整範圍、來源、驗證證據、人工驗收與合併結果；Sheet 保存必要狀態。交付驗收前，同一批更新 repo 文件。PROGRESS 留已交付範圍、驗證版本、PR 連結與下一步；驗收與合併狀態以原 PR 為準。已交付的 TODO 改由 PROGRESS 的 PR 索引追蹤，不在 TODO 再留一份結案紀錄。不預寫「已驗收」，也不改寫既有歷史紀錄。驗收結果與實際 merge SHA 只在發生後回寫原 PR，並依 SNAPSHOT 把必要狀態精準寫入 Sheet 與回讀；不為驗收或合併 SHA 另開只改文件的提交。
- Sheet 批次依其 README／Handoff Protocol 更新 Project State、Status 與一筆必要結案 Changelog；翻譯或結構異動另記對應事件，避免為同一狀態重複新增紀錄。按 SNAPSHOT 的寫入規則先讀鍵值、範圍及序號，再精準寫入與回讀。正式快照須同次擷取書本 Master 的 Glossary／Names／Strings 與 Forge Steel Master 的 UI／Adaptations／Adaptation Sources 六個分頁的核准資料（含適用的動態 Note）；兩份來源分別核對讀取前後修改時間，不一致即停止，不能沿用舊 Note。

## 驗證

- 完整入口 `node scripts/l10n/verify.mjs`：守門（含匯出一致性）→ Lint → TypeScript → Vitest → 正式建置 → audit。前項失敗仍跑後項，任何失敗整體 exit 1。CI 使用同入口、六項分開顯示；必要狀態 l10n 覆蓋六項。
- 上游 `npm run check` 保持原樣；完整入口已涵蓋其要求，不重複相同檢查。`--only` 只供定位／補跑，不能當成整體通過；audit 使用本批實際結果，不沿用舊數量或忽略漏洞。
- 本機有使用中的開發伺服器或需乾淨安裝時，優先 `node scripts/l10n/verify-isolated.mjs`：複製目前追蹤檔與未忽略的新檔，保留尚未提交的修改及刪除；在系統暫存區的副本 `npm ci`、完整 verify、瀏覽器回歸，最後清理副本。副本位於原工作目錄之外，TEMP／TMP／TMPDIR 只對子程序設在副本內，測試伺服器不監看暫存 profile；不改 workers／逾時。前後來源指紋不同就失敗，不能把舊副本結果當成目前工作樹通過。忽略檔與使用者瀏覽器 profile 不複製；CI 沿用既有乾淨 checkout。
- Sass／暫存／權限異常先 `node scripts/l10n/verify.mjs --doctor`；診斷包含 sass-embedded 套件、實際編譯器啟動及暫存目錄寫入。不要在使用中工作目錄執行 `npm ci`，也不以補拷部分 node_modules 作為乾淨安裝證據。副本在一般成功／失敗時清理；強制終止留下的目錄須依命令輸出的完整路徑，確認其位於系統暫存區且名稱為 `forgesteel-l10n-verify-*` 再清理。
- 開發期間依需要跑相關回歸；最後一次程式／翻譯／設定變更後，執行一次完整驗證。完整驗證已包含目標測試時，不必先重跑同一批目標測試。若完整驗證失敗，再用單檔或 `--only` 定位；修正程式後重新跑完整驗證。共用機制涵蓋數值、計算開關、語言切換、未知備援、資料不變；少量可重複瀏覽器檢查旅程與列印 DOM，不截圖、不錄影。
- 總數只在 inventory.test.ts 集中，批次測試驗自己的鍵與行為。同一份未再變更的程式版本只跑一次完整驗證；程式、翻譯資產或相關設定再次變更時重新驗證。該次完整驗證已含守門與匯出一致性時，不另手動執行 `node scripts/l10n/export-sheet.mjs --check` 或 `node scripts/l10n/check.mjs`。快照工具的 dry-run 與 `--apply` 安全檢查仍照 SNAPSHOT 執行。同程式版本只改文件時，引用該版本既有驗證的日期、版本與限制，只檢查文件 diff、連結與一致性。隔離驗證若在乾淨安裝階段因 npm／registry 環境失敗，先記錄並檢查環境；環境沒有改變前不重複相同安裝。
